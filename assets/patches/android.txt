The entire Fenix UI is localised through in-tree res/values-*/strings.xml (mobile/android/fenix/l10n.toml has basepath = "."), so --with-l10n-base and the repo's l10n/ overlay reach NONE of it - 144 values*/**/*.xml files across 131 locale directories in mobile/android/fenix/app/src/main/res (reproduce: find mobile/android/fenix/app/src/main/res/values*/ -name '*.xml' | wc -l). The patch adds mobile/android/lw-brand/ (rewriter, brand map, android-l10n pin, Gradle glue, host-side UI scanner, and a check-apk gate) and one `gradle.projectsLoaded { -> apply from: brand-strings.gradle }` hook appended to mobile/android/shared-settings.gradle; the rewrite runs per module as :<module>:lwBrandStrings, writes a rewritten copy of each res dir into that module's build directory and REPLACES res.srcDirs with it, so the source tree is never mutated (contrast landmine L4) and an overlay cannot collide with the original as a duplicate resource. It touches NO build.gradle. The gate - scripts/android-smoke.sh --check-strings - reads the BUILT apk's resources.arsc with aapt2 and runs the patch's own checker: a string/plurals/string-array value FAILS iff a brand stem (Latin or non-Latin) still fires outside the enumerated url-keep hosts and the internal-key (value==name) exception, so a shallow two-screen scrape cannot pass it. Measured on the built APK (236,631 vs 234,641 string rows, pre- vs post-rewrite release): unexplained brand values 6,170 -> 0, with 297 url-keep rows left - firefox.com in sign_in_instructions (108) and pair_instructions_2 (106), and Google's client=firefox suggest example in search_add_custom_engine_suggest_string_example_2 (83) - and exactly 3 of the 457 value==name internal keys carry a brand stem (pref_key_enable_firefox_labs, pref_key_enable_mozilla_ads_client, pref_key_firefox_labs) and are deliberately untouched, since rewriting a pref key corrupts stored preferences. 43 word stems in the brand map, 32 of them non-Latin across 19 locales (Arabic, Cyrillic, Devanagari, Tamil, Telugu, Sinhala, Malayalam, Kannada, Saurashtra and the Arabic-script variants), so an ASCII sed is not enough; the per-locale spellings are DERIVED from the android-l10n commit pinned and sha256-verified in mobile/android/lw-brand/android-l10n-pin.txt. Anything the map cannot clean is dropped from the translated file and falls back to the rewritten English string (per-module build/lw-brand/dropped.txt lists them). Its only shared-file hunk is an append to mobile/android/shared-settings.gradle, a file no other Android patch touches, so it is order-free with build-fixes.patch and no-gms.patch (both of which DO touch the root build.gradle)
patches/android/r8-keep-rules.patch                     # LW-M6-07: restores third_party/application-services/proguard-rules-consumer-jna.pro, which third_party/application-services/build-scripts/component-common.gradle ALREADY declares (consumerProguardFiles, release block) but which is absent from the ESR tarball (tar -tJf, checked 2026-08-20; the per-component android/proguard-rules.pro files are empty boilerplate, not a substitute). Without it the in-tree Nimbus AAR ships with zero consumer ProGuard rules and fenix:assembleRelease's R8 strips the @Structure.FieldOrder runtime annotation off the uniffi RustBuffer classes, so com.sun.jna.Structure.getFieldOrder() returns an empty name list and the app dies on launch - the LW-M4-09 crash, reproduced in ~/lw-m4-09/evidence/release-r8-crash.logcat. This is why every 'release' APK built so far needed -PdisableOptimization. Content byte-identical to upstream Mozilla's file (application-services main, 949 bytes, cmp'd). Touches a file no other patch in either list touches, so no ordering constraint; stays in android.txt because the file is a pure Gradle build input the desktop build never consumes - the desktop tree must stay byte-identical to stock. See the patch header for the full evidence chain
