# Patches applied to every target.
#
# scripts/librewolf-patches.py applies this list first, then desktop.txt
# and/or android.txt according to --targets. Paths are relative to the repo
# root. Blank lines and '#' comments are ignored; everything else is a patch
# path, applied top to bottom.
#
# These lists are the ONLY patch inputs. The old assets/patches.txt shim - a
# generated common+desktop concatenation kept for downstream builders - was
# retired by LW-M7-01 and no longer exists; do not regenerate it. The patcher,
# scripts/check-patchfail.sh, scripts/fuzzfail.sh and the enable/disable helpers
# all read assets/patches/*.txt directly.
#
# ORDER IS LOAD-BEARING. Four pairs share a tree file and only apply in one
# order (docs/android/AGENTS.md, "Patch ordering constraints"). Two of them
# are entirely inside this file:
#
#   autoconfig-setEnv  before  profile-directory        extensions/.../prefcalls.js
#   firefox-in-ua      before  moz-configure            toolkit/moz.configure
#
# The other two hold across files, because common.txt is applied first. The
# webgl pair was within this file from LW-M1-08 until the Firefox 157 merge
# moved its second half out (to both target lists, see below):
#
#   fpp-canvas-fix (here)  before  webgl-permission-common (desktop.txt)
#                                  and android/webgl-permission-common-esr (android.txt)
#                                  dom/canvas/ClientWebGLContext.cpp
#   mozilla_dirs   (here)  before  xdg-dir          (desktop.txt)
#
# STATUS: REVIEWED by LW-M1-01. Every entry below was opened and classified by
# what it does, against the pristine firefox-153.0.4 tree; the per-patch
# evidence is the "why common" column in docs/android/PATCH-SCOPE.md. The
# heuristic '(?)' markers left by LW-M0-02 are resolved and gone. Five entries
# that used to sit here moved to desktop.txt - each was demonstrated inert on
# Android by a build guard, not assumed inert from its filename:
#
#   add-mojeek                      services/settings/dumps/main/moz.build:46
#   dbus_name                       toolkit/components/remote/moz.build:25-35
#   macos-relaunch-without-updater  .mm, toolkit/xre/moz.build cocoa-only
#                                   (deleted upstream for Firefox 157; gone)
#   ui-patches/lw-logo-devtools     devtools/moz.build:5-8 (MOZ_DEVTOOLS=all)
#   xdg-dir                         nsXREDirProvider.cpp:1309-1539 MOZ_WIDGET_GTK
#
# Two entries left this file in the Firefox 157 desktop merge, because upstream
# LibreWolf deleted them and the desktop tree no longer needs them. Android
# (still firefox-153.0esr, version.android) does, so each moved VERBATIM to an
# android.txt entry under patches/android/ - not dropped:
#
#   bootstrap                         -> android/bootstrap-esr (upstream cd7ec6e7)
#   fix-canvas-extraction-permission  -> android/fix-canvas-extraction-permission-esr
#                                        (upstream d374f724: fixed in Gecko by 157),
#                                        itself dropped at the 153.4.0esr rebase:
#                                        Gecko 153.4.0esr carries the fix too
#
# A third, webgl-permission-common, did not leave upstream but was REWRITTEN for
# 156/157 (upstream 93145180, 68e31784, a2b2389c, 8ed75571: OffscreenCanvas and
# worker gating, clang-format). The 157 text now lives in desktop.txt under the
# same name; the 153 text Android was built and verified against (LW-M7-14's
# ClientWebGLContext hunks quote it) moved VERBATIM to
# android/webgl-permission-common-esr. Both still need fpp-canvas-fix first.
#
# Three more were SPLIT the same way because one text cannot apply to both
# trees (each proven by applying the full list order to the pristine
# firefox-157.0 and firefox-153.0esr tarballs). The 157 text keeps the name and
# moved to desktop.txt; the text Android was built and verified against moved
# VERBATIM (byte copy of the pre-merge file) to android.txt:
#
#   always-fetch-latest-toolchain-artifact  -> android/always-fetch-latest-toolchain-artifact-esr
#       upstream 9f21b38c rewrote it for 157; its import hunk rejects on 153
#   remove-openai                           -> android/remove-openai-esr
#       157's toolkit/components/ml/jar.mn dropped context the 153 text quotes;
#       the desktop text was regenerated from the 157 tree (landmine L4
#       tripwire lines intact - see the patch header)
#   ui-patches/neterror-common              -> android/neterror-common-esr
#       upstream 3ac002b0 rewrote net-error-card.mjs's hunk for 156; it rejects
#       on 153. Pairs with neterror-desktop (desktop) / android/neterror-jar
#
# Three more left for a different reason: their 157 text still APPLIES to
# firefox-153.0esr, but upstream changed what it does for 156/157, so applying
# it would change the Android tree. Android's patched 153.0esr tree is held
# byte-identical to the pre-merge one, so the text Android was built and
# verified against moved VERBATIM to android.txt and the 157 text moved to
# desktop.txt, at the HEAD of that list (they were common.txt entries, i.e.
# applied before every desktop.txt patch, and still are):
#
#   rs-blocker                      -> android/rs-blocker-esr
#       upstream 5b4201be/3536d182: startup-bundle bucket filter, blocked
#       collections as debug logs, new remote-settings.sys.mjs and
#       ConfigSearchEngine.sys.mjs hunks
#   vendor-name                     -> android/vendor-name-esr
#       upstream 81e96593: getBrowserInfo() reports MOZ_APP_VERSION_DISPLAY
#   disable-data-reporting-common   -> android/disable-data-reporting-common-esr
#       upstream a1bd18fa/fb4c7a32/77f8fcd8: the Stopwatch/UserInteraction hunks
#       were added and the mach.txt / glean init hunks became version-specific
#       (see the header of patches/disable-data-reporting-common.patch). Android
#       applies it with android/disable-data-reporting-android, as before.
#
# Re-merge these six and webgl-permission-common into this file when Android
# moves to an ESR >= 157 (bootstrap-esr is simply dropped then;
# fix-canvas-extraction-permission-esr already was, at 153.4.0esr).
#
# Nothing was dropped from this file to make a build compile, and nothing may
# be. See "What not to do" in docs/android/AGENTS.md.

patches/xmas-common.patch                               # LW-M1-09 common half of the old xmas straddler: root moz.build `DIRS += ["lw"]` + lw/moz.build. Desktop half is patches/xmas-desktop.patch
patches/eme-permission-common.patch                     # LW-M1-03 common half of the old eme-permission straddler: dom/media/eme/MediaKeySystemAccessManager.cpp only (dom/media/moz.build:28,32 puts "eme" in DIRS with no guard). No other patch in any list touches that file, so its position here is free. Desktop half is patches/eme-permission-desktop.patch
patches/moz-official-common.patch                       # LW-M1-04 common half of the old moz-official straddler: the two CDM host-verification hunks, dom/media/gmp/ChromiumCDMAdapter.cpp (dom/media/moz.build:28-36 DIRS has "gmp" unguarded; gmp/moz.build:65-67 UNIFIED_SOURCES) and media/gmp-clearkey/0.1/gmp-clearkey.cpp (toolkit/toolkit.mozbuild:167-169 DIRS is unconditional, and clearkey moz.build:13-16 has an explicit Android FINAL_TARGET branch, i.e. it is packaged into the APK). No other patch in any list touches either file, so its position here is free. Keeps librewolf.eme.gmp-clearkey.enabled meaningful on Android - without it an unsigned build cannot create a clearkey CDM even when the pref is on. NO Android companion patch; desktop half is patches/moz-official-desktop.patch
