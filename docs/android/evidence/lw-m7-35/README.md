The new `nsIPrefService.savePrefFileAsync()` forces an ordered current-profile snapshot and resolves only its actual write success. No initialized profile or profile shutdown rejects before any snapshot. Each `PWRunnable` owns its snapshot/destination/promise on the existing serial I/O target; the old shared snapshot could be consumed by another request or written to another file. The old callback also resolved a failed write as true. Dispatch failure explicitly rejects and balances the pending count, even if dispatch retains the runnable. Blocking saves obtain the wrapped write result (SyncRunnable itself only reports dispatch status), force the latest snapshot even when the dirty flag was cleared by an earlier asynchronous save, and preserve pre-profile backup flushing. Failed final saves do not mark the profile shut down. Dirty/error bookkeeping stays on the main thread; promise completion uses the real I/O result independently. Cancellation releases the file on the main thread. This Android-only registered patch also changes legacy pref-save/backup scheduling from shared coalescing to distinct snapshots: additional writes/memory are an explicit cost.
