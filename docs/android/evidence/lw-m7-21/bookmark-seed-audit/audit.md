# NoDefaultBookmarks: existing Android counterpart, runtime pending

Read-only audit of the pinned beta source and current repository policy. No source, task metadata, VM, device, bookmark database or key was changed. No native test was executed. **No new code change is justified by the observed implementation.** A source-level counterpart exists: Android initializes empty bookmark folders and has no observed upstream URL-bookmark seed in this startup path. Actual final APK/fresh database behavior remains pending.

`source-inputs.json` gives full paths, sizes and SHA256 hashes for all 36 archived inputs. `source-inputs.tar.gz` retains the exact files. Archive SHA256: `84168a3e599726f327a75675d92ba54681783c7018aca22ecd968d8abdb3b48b`.

Observed chain:

- Repository `settings/distribution/policies.json:75` sets `NoDefaultBookmarks: true`. Desktop `browser/components/enterprisepolicies/Policies.sys.mjs:2208` disallows `defaultBookmarks`. `browser/components/places/PlacesBrowserStartup.sys.mjs:198–225` selects `chrome://browser/content/default-bookmarks.html` / profile HTML and checks the allowed feature before importing. This is a desktop startup HTML-import gate, not a command to erase user bookmarks.
- Fenix `FenixApplication.kt:430–438` queues storage warmup after visual completeness. `components/Core.kt:586,611` supplies `PlacesBookmarksStorage(context)`. A-C `PlacesStorage.kt:44–67` uses `context.filesDir` and initializes reader/writer. `Connection.kt:14,67–72` opens **app files/places.sqlite**, through `PlacesApi`; it is not the Gecko profile's similarly named desktop Places database.
- In-tree `components/places/src/api/places_api.rs:140–167` opens a read-write connection on first initialization so schema creation/migration can run. `src/db/db.rs:52–53` calls `schema::init`; `src/db/schema.rs:75–79` executes `sql/create_shared_schema.sql`, then calls `create_bookmark_roots`.
- `src/storage/bookmarks.rs:31–70` inserts exactly five **folder** rows, with no URL/fk value: root, menu, toolbar, unfiled and mobile. `root_guid.rs:55–59` gives `root________`, `menu________`, `toolbar_____`, `unfiled_____`, `mobile______`. `types.rs:126–127` distinguishes URL bookmarks (type 1) from folders (type 2). Therefore an empty fresh bookmark store is expected to have five structural rows; requiring an empty `moz_bookmarks` table would be wrong.
- The backend binding is explicit: repository `assets/mozconfig.android:173` enables `--enable-appservices-in-tree`; root `settings.gradle:36–38` conditionally loads `third_party/application-services/settings.gradle` on `MOZ_APPSERVICES_IN_TREE`. The vendored `moz.yaml` pins revision `06c391e81c367d1059d601c812f379875d7ef0a3`. The fallback A-C dependency config names release 153.0. Final evidence must retain the actual resolved in-tree flag/artifact manifest; the vendored audit alone is not proof about an arbitrary Maven/backend replacement.

Other paths do not provide a default seed:

- The inspected Fenix distribution classes update distribution identity/provider state; bounded searches found no bookmark resource/import consumer there. Fenix's storage warmup contains no default bookmark URL input. Searches of production Fenix Kotlin, the A-C storage bridge and native Places source found no `default-bookmarks.html` / `bookmarks.html` initialization consumer.
- User **Bookmark page** is real: `components/menu/compose/MainMenu.kt:417` displays it; `MenuDialogMiddleware.kt:249–272` calls the bookmark use case for the selected page; `BookmarksUseCase.kt:61–87` resolves the saved folder or Mobile root and calls `storage.addItem`; `PlacesBookmarksStorage.kt:139–143` calls native `createBookmarkItem`. Toolbar and selected-tabs actions are additional explicit user insertion routes.
- File import is user-triggered: `BookmarkFragment.kt:157–162` opens `ImportBookmarksDialogFragment`; its importer asks for a document, parses the chosen URI and calls `insertTree`. `HtmlBookmarksFileImporter.kt` has no initial bundled file. Sync can legitimately supply user bookmarks; `BackgroundServices.kt:119,135` registers that store. A clean baseline must exclude account Sync, restore/migration and an operator-selected import, rather than deleting their resulting data.
- Task 30 is separate. `DefaultTopSitesBinding.kt:56–73,78` reads `R.raw.initial_shortcuts` after region state and invokes `topSitesStorage.addTopSites(..., isDefault=true)`. Core has a separate `PinnedSiteStorage` and top-sites composition. Emptying that resource fixes default home shortcuts, not bookmark-table initialization. It must not become evidence that all user bookmarks are disabled.

Existing coverage limitation: `PlacesBookmarksStorageTest.kt:34–37` explicitly calls `bookmarks.writer.deleteEverything()` in setup. Its empty-child/root assertions at 47–83 and manual insertion tests prove behavior after cleanup; **they cannot establish a fresh APK had no seeded bookmarks before cleanup**. Coverage 17 currently leaves this family `mixed_open`; root can record the existing source counterpart, with actual fresh/restart/upgrade behavior pending.
