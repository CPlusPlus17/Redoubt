## Available API and storage semantics

The generic route already exists end to end:

- `frozen/mobile/android/android-components/components/concept/engine/.../preferences/BrowserPreferencesRuntime.kt` (implemented by Engine) exposes getBrowserPref(s), setBrowserPref(s), clearBrowserUserPref and observers.
- `frozen/mobile/android/android-components/components/browser/engine-gecko/.../GeckoEngine.kt:1274–1450` delegates through `preferences/GeckoPreferenceAccessor.kt` to GeckoPreferenceController.
- `frozen/mobile/android/geckoview/src/main/java/org/mozilla/geckoview/GeckoPreferenceController.java` is experimental and HandlerThread-bound; its Java value object has type/defaultValue/userValue and computed effective-ish value, but no lock field.
- `frozen/mobile/shared/components/geckoview/GeckoViewPreferences.sys.mjs:23–163` reads native prefs and performs arbitrary typed user/default writes. SetPref maps requests sequentially to booleans, so batches can partially mutate; no prevalidation, locks, awaited storage or reread. ClearPref simply clears user branch and acknowledges. A locked pref can retain a stored user value while returning the effective default through Services.prefs; this API does not expose that distinction.
- GeckoViewStartup.sys.mjs:262–287 registers this module. Fenix NimbusGeckoPrefHandler already consumes the generic engine API, so changing its semantics globally would have other clients.

Thus real values can already be read/set, but **a narrow new operation/state contract is needed for reliable product controls**, unless the existing generic API is explicitly extended with those semantics. Recommended allowlisted controller supports exact types/ranges, native effective/default/has-user/locked state, rejects locked/unknown/invalid writes before mutation, serializes relevant writes/resets, awaits the task35 current-profile save primitive, and returns refreshed native state. UI must distinguish memory changed/save failed from durable success; do not invent rollback of concurrent changes. Reset clears user pref and awaits saving; it should not rewrite an assumed default or erase site permissions. No Fenix SharedPreferences mirror.

Autoconfig authority is concrete: `frozen/extensions/pref/autoconfig/src/prefcalls.js:64–126`: pref writes user branch, defaultPref writes default branch, lockPref sets default and locks. A comment saying LOCK is not a lock. Current audited global inputs are not lockPref entries, but snapshots must detect administrator/user locks at runtime. defaultPref permits a persisted user override. Plain webgl.disabled pref does not. An Android correction must prevent the plain write before it destroys the loaded user choice; a later defaultPref override cannot recover it. If desktop semantics must remain byte-identical, move this setting out of common into desktop plain pref and Android defaultPref, regenerate canonical config by the normal split workflow. This is a proposed implementation choice, not an edit made here.

Avoid registering these as ordinary GeckoRuntimeSettings.Pref values: `RuntimeSettings.java:353–367` clears user prefs it owns at startup; runtime commits write defaults and getters return cached Java values. The audited names are absent from current GV runtime-setting declarations. Existing fingerprinting protection declarations at GeckoRuntimeSettings.java:817–822 name privacy.fingerprintingProtection, not RFP.

## Task35 overlap and implementation ordering

Task35 owner chose a narrow extension-update operation in existing WebExtensionController/GeckoViewWebExtension, leaving generic BrowserPreferencesRuntime unchanged. Reuse its new `nsIPrefService.savePrefFileAsync()` native current-profile durability primitive. Its native Preferences.cpp/nsIPrefService.idl work must land first; the frozen SavePrefFile(null) only schedules, and the existing BackupPrefFile promise explicitly disallows the current file. Existing PWRunnable has coalesced snapshot and false-success failure defects under independent review; do not claim durability until that patch and target tests pass.

A later scoped global-control task can add a dedicated controller/state module, GV public API and registration, A-C typed interface/GeckoEngine delegation, and one Fenix settings fragment with non-persistent preferences. Likely shared paths with35: GeckoEngine.kt, Engine/engine interfaces, Fenix SettingsFragment.kt, res/xml/preferences.xml, res/values/strings.xml and preference_keys.xml, and GV API signature lists/GeckoViewStartup if the new controller needs registration. Dedicated classes reduce source overlap. Do not add these values to RuntimeSettings reset lists or a Fenix startup mirror. Global WebGL default correction also touches the settings split/generator inputs and must preserve already integrated defaults.

## Minimum meaningful acceptance

1. Host/JS tests cover allowlist, enum0/1/2 preservation, locked/default/user states, nonboolean values, partial-batch rejection, failed save and concurrent write/reset, effective reread, untouched per-site grants. Existing GV `PreferencesTest.kt` covers raw get/set/clear/observers but not durable acknowledgment; extend target coverage for the new operation. Existing GeckoEngineTest.kt generic preference cases are useful delegation patterns, not native persistence proof.
2. Real packaged Fenix UI control -> native state acknowledgment -> immediate force-stop -> restart state, with fresh default and reset controls and actual APK/hash/profile evidence. Check profile with explicit prior user prefs too. Enforce no debug pref injection for release acceptance.
3. RFP: page and fresh worker observations before/after reload, normal/private, restore default; record pbmode and applicable overrides, not only one pref value.
4. WebGL: default per-site protected state; actual global Always allow enables new context without a grant; restore permission-required mode and demonstrate preserved grants/blocks; quiet false/true changes actual prompt visibility while denial policy remains enforced. Optional global disable prevents newly created DOM/offscreen/worker WebGL even for a granted site; reenabling and restart preserve expected state. Do not claim destruction of preexisting contexts from a pref write.
5. IPv6: controlled uncached dual-stack host DNS and actual network receipts, IPv4 positive control, restore; record transport/TRR setting rather than changing it to produce the expected result.
6. Referrer: controlled HTTPS pages/resources with server-observed Referer for same host/different port, sibling subdomain and different registrable domain; mode1 vs2, trimming still enforced, reset and restart. Native host semantics must determine UI wording and expected receipts.

All APK, effective runtime, durability, document propagation, worker, network and UI acceptance is **pending**. This audit establishes existing engine capabilities plus missing reliable Android global controls and a concrete route to implement them; it does not count a pref-only letterboxing setting as a feature.
