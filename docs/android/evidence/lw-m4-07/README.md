# LW-M4-07 — Firefox brand imagery removed, and uBO verified in the same build

## What was wrong

The signed 2026-09-08 beta candidate satisfied all twelve `BETA.md` entry criteria
and still shipped Mozilla's trademarks. Found by inspecting the signed APK, not
the sources:

- the home screen's wordmark was the **full-colour Firefox flame**
  (`ic_wordmark_logo`) with the word **"Firefox"** beside it
  (`ic_wordmark_text_normal`);
- `ic_firefox`, `expressive_firefox`, `firefox_icon`, `mozac_ic_logo_firefox_24`
  and `firefox_pictorgram_shield_check_rgb_2` were Mozilla's logos;
- **eight alternative app icons** shipped with a Settings picker, including the
  classic 2004 Firefox logo and the flame — a user could set their launcher icon
  to the Firefox logo on a browser called Redoubt.

`firefox-branding-before.png` is those assets, extracted from that APK.

It also had **no uBlock Origin**. LW-M3-07 landed at 23:02 on 2026-09-08; the
candidate was built at 16:13, seven hours earlier.

## Why nothing caught it

No gate this project owns looks at images. `--check-strings` cleaned the string
table and the rendered settings text and passes honestly — re-checked on the
candidate, only six Firefox mentions survive and every one is a documented
exception (`firefox.com/pair`, pref keys whose value is their own name).
`--check-scope`, `check-patch-order` and `check-patchfail` care whether patches
apply, not what they contain.

LW-M4-07's acceptance line 2 — *"no Firefox or Mozilla trademark in the app name,
icon, or store listing"* — was **true**: the launcher icon and app name were
already Redoubt's. It just did not cover in-app imagery.

## The fix

76 replacements, generated by `scripts/gen-android-brand.py` and checked in under
`assets/android-brand/`, copied over the originals by `librewolf-patches.py`
`android_brand_images()`. Classification is by shape, not name: wordmark text
becomes "Redoubt", wide rasters become a mark-plus-word lockup at the original's
exact pixel size, everything else becomes the four-bastion fort the launcher icon
already uses.

`scripts/android-brand-check.py` is the new gate and runs in CI after `make dir`.
It fails when upstream adds brand art the replacement set does not cover, which is
the failure that matters on a rebase. All three exit codes exercised.

## Verified on the running build

`home-screen-after.png` — the home screen of the rebuilt candidate:

- the wordmark is the **Redoubt fort and the word "Redoubt"**;
- **"uBlock Origin was added"**, installed on first run.

| check | exit | result |
|---|---|---|
| `--check-ubo-preinstall` | **0** | uBO present and installed from the pinned XPI |
| `--check-strings` | **0** | resource table 234,762 rows, 0 unexplained; 36-screen running-app traversal |

APK contents: `assets/extensions/ublock_origin.xpi`, 4,617,614 bytes — the exact
size pinned in `assets/ubo-extension.json`.

## Two compile breaks found on the way

The branch had not been built since 2026-09-09 and did not compile:

1. `firefox-suggest-data.patch` makes Fenix reference
   `mozilla.appservices.suggest` without adding the Gradle dependency.
   `feature-fxsuggest` declares it `implementation`, so it is not on Fenix's
   compile classpath. Twelve errors at `:fenix:compileReleaseKotlin`.
2. `global-privacy-controls.patch` left a redundant safe call that `-Werror`
   rejects.

Both are the same shape as `update-check.patch` in September: applies cleanly,
passes every patch gate, does not compile.

## Gecko's branding layer, done afterwards

The first pass covered Fenix's Android resources. Gecko ships its own branding
underneath, and it was still Mozilla's — `assets/mozconfig.android` builds
`--with-branding=mobile/android/branding/unofficial`, whose upstream contents are:

    MOZ_APP_DISPLAYNAME="Fennec"
    -brand-short-name   = Fennec     -brand-full-name   = Mozilla Fennec
    -brand-product-name = Firefox    -vendor-short-name = Mozilla
    content/about.png                a fennec-fox logo reading "mozilla Fennec"

Those compile into `omni.ja` and travel inside the APK — read out of the signed
artifact, not inferred. `--check-strings` cannot see them: it reads the Android
resource table, and `omni.ja` is not in it. Same blind spot as the images, one
layer down.

**Where it surfaced is narrower than it looks**, and is recorded so nobody
re-derives it: error pages are Fenix's own and say "The browser", not "Fennec";
`about:rights`, `about:support` and `about:buildconfig` are all unavailable on
Android. No screen was found that displays it. So this was trademark hygiene in
the shipped artifact rather than a visible defect — worth fixing because "we
could not find where it renders" is a weaker answer than "it is not there".

Now, read back out of the rebuilt APK's `omni.ja`:

    -brand-short-name = Redoubt      -brand-full-name   = Redoubt
    -brand-product-name = Redoubt    -vendor-short-name = Redoubt

`gecko-branding-after.png` is that build's `about.png`.

The directory keeps its upstream name. Renaming it would mean editing
`assets/mozconfig.android`, which another task owns and a gate diffs, and
"unofficial" is accurate — this is not a Mozilla-official build.

`android-brand-check.py` now checks this layer **by value, after patching**: the
question is whether the artifact still says Fennec, not whether a file was
written. It caught all seven strings before they were replaced.

Two defects found in the generated output itself, both by rendering it and
looking rather than trusting the code:

- Gecko's `about.png` is 258x94, where type sized from the image height
  overflows: the word rendered as "Redou". The lockup now fits type to the
  remaining width.
- The generator was not deterministic — three PNGs differed byte-for-byte every
  run at identical pixels (`compare -metric AE` = 0), because ImageMagick writes
  a creation timestamp. Harmless to the reproducible build, since the bytes are
  committed, but it buries real changes in encoder noise. Fixed and verified by
  generating twice and hashing the set.
