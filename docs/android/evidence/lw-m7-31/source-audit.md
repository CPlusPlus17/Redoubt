# Observed permission completion chain and patch boundary

All source below was opened from `librewolf-153.0esr-1-beta-20260908`; only isolated `lw-m7-31/source` files were changed. The GeckoView module baseline also includes the committed LW-M7-12 readiness patch. Exact candidate/baseline hashes are in `source-files.json`.

| Actual source | Observed behavior and implication |
| --- | --- |
| `mobile/shared/modules/geckoview/GeckoViewWebExtension.sys.mjs`, `setPrivateBrowsingAllowed`, `GeckoView:WebExtension:SetPBAllowed` event handler | Calls public `ExtensionPermissions.add/remove`, reloads an active add-on, exports the extension, then sends success. The driver calls this exact production method; it neither writes internal stores nor uses test-only permission APIs. |
| `toolkit/components/extensions/ExtensionPermissions.sys.mjs`, `createStore` and `LegacyPermissionStore` | Non-Nightly production selects legacy storage using `AppConstants.NIGHTLY_BUILD`. `_useLegacyStorageBackend` is a test switch, not the production selector. Legacy put/delete return after `JSONFile.saveSoon()`, before the real write. Public add/remove mutate the arrays returned by `_get`, so merely adding a failing awaited flush would leave a false committed value and could suppress a same-choice retry. |
| `toolkit/modules/JSONFile.sys.mjs`, constructor, `saveSoon`, `_save` | The `data` setter at lines 195–198 only assigns `_data` and `dataReady`; it does not arm a saver. `saveSoon` at 406–408 explicitly arms it. The default save delay is 1500 ms; `_save` catches/reports the write error. A caller awaiting that caught error cannot establish success. The new Android store uses the existing initialized JSONFile path/data but writes through IOUtils directly, with a whole-file serial queue and memory publication after success. A profile-before-change blocker retains the complete queued writes during graceful shutdown; completed-call errors still reach their caller. Desktop still uses JSONFile's scheduling. |
| `dom/chrome-webidl/IOUtils.webidl`, `writeJSON`, `WriteOptions.tmpPath/flush` | `writeJSON` rejects on failure; `tmpPath` makes the replacement atomic and `flush` requests buffer flushing. This is the source-supported completion boundary. Real OS/device persistence and abrupt process-death behavior still require target execution. This is not a power-loss/filesystem hardware guarantee. |
| `toolkit/components/extensions/ExtensionTaskScheduler.sys.mjs` | Public API queues serialize writes by extension ID and allow independent IDs. A second queue is needed because legacy IDs share one file and temporary path. Host tests execute this actual scheduler, including queued read/revoke and distinct-ID changes. |
| `toolkit/components/extensions/ExtensionParent.sys.mjs`, `CacheStore` and `StartupCache` | The permission cache is a separate `ProfLD/startupCache/webext.sc.lz4` file, saved with its own 5000 ms DeferredTask. `_getCached` previously trusted it. Completing the JSON write alone can still expose an old grant or denial after restart. Android now reads the authoritative JSON/KV store and refreshes the derived entry when needed, preserving existing cache-warming expectations. KV put/delete calls are unchanged. |
| `toolkit/components/extensions/Extension.sys.mjs`, `ExtensionAddonObserver.onUninstalled/clearOnUninstall` | `onUninstalled` starts `ExtensionPermissions.removeAll` but returns without awaiting it. The existing `cleanupAfterUninstall` event publishes `{name, promise}` tasks after registration. The exact permission task name is `Clear ExtensionPermissions for ${addonId}`. |
| `toolkit/mozapps/extensions/internal/XPIInstall.sys.mjs`, `uninstallAddon` | Calls `onUninstalled` synchronously before the normal uninstall method finishes. The LW-M7-19 persistence barrier covers its add-on state, not the separate permission cleanup promise. GeckoView now registers the exact-ID cleanup listener before uninstall, awaits that original task afterward, and detaches in `finally`. Missing/duplicate matching task within the notification, wrong ID and task failure cannot acknowledge success. It does not retry cleanup or wait on unrelated extension storage tasks. |
| `toolkit/components/extensions/ExtensionTestCommon.sys.mjs`, `ExtensionUninstallTracker` | Existing tests already use `cleanupAfterUninstall` to await the collected tasks. The production patch uses the established production event directly; no testing-common code is imported into production. |
| `toolkit/components/extensions/test/xpcshell/test_ext_permissions.js`, `test_ext_permissions_uninstall.js`, `head_legacy_ep.js` | Existing target tests exercise public APIs and cache population, use explicit test-only store selection, and separately await uninstall cleanup. The actual `head.js` defines lazy `ExtensionParent` at line 33, `Management` at 37 and `TestUtils` at 43; the new test uses those exports and initializes AddonTestUtils/appinfo before importing GeckoView. These should run alongside the new Android definition to check compatibility. |

The ordinary UI route, actual resource selectors, source-bound package/filter checks and signed-update proposal remain in LW-M7-28 evidence. The updated removed-state observer uses public `ExtensionPermissions.get` and, on production legacy builds, reads the JSON file independently. It does not call removeAll or otherwise manufacture revocation. A removed registry row alone cannot pass.

Important limits: production `removeAll` remains asynchronous for its other callers; this patch specifically strengthens the Android GeckoView public uninstall completion. Permission-cache I/O performance on Android should be checked on target, especially for modern KV builds, since reads now consult the authoritative backend. The uninstall task-name binding is deliberate and pinned to the observed observer contract; a future observer rename fails explicitly and requires updating the bridge and tests. No origin/private isolation policy, enterprise permission policy, default private grant, add-on signature setting or modern KV recovery policy is changed.
