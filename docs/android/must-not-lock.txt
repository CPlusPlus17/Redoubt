# GeckoView pref decisions (LW-M3-04)
#
# Consumed by `python3 docs/android/board.py --check-policies`. EVERY pref that
# GeckoView declares and we ship UNLOCKED must appear in exactly one section below.
# Absence is a hard error.
#
# WHY THIS FILE GREW TEETH ON 2026-08-27
# --------------------------------------
# It used to be a four-line advisory list, and --check-policies was satisfied by the
# STRING "[ANDROID: LOCK]" appearing in a comment near the pref. A comment. So of the
# 26 GeckoView-declared prefs we ship on Android, 23 were effectively defaultPref and
# the gate was green over all of them. A marker recorded that somebody had thought
# about the question; it never recorded the answer.
#
# All 23 were then classified against the code. The alarming headline did not survive
# contact: 14 are genuinely safe unlocked. But the ones that were not safe were not
# peripheral either -- see NETWORK.TRR below.
#
# THE THREE SECTIONS
#   MUST-NOT-LOCK        a visible setting owns it; locking makes that control a
#                        silent no-op. Every entry names the UI.
#   SAFE-UNLOCKED        nothing writes it at stage 5b, so the unlocked defaultPref
#                        already survives. Every entry says why.
#   LOCKED-CONTROL-DEAD  deliberately locked, knowingly leaving a control inert.
#
# Stage 5b = Fenix Pref.commit() -> GeckoView:SetDefaultPrefs, ~65 of which fire on
# every cold start from GeckoEngine.kt with no user interaction. See AGENTS.md, L2.
