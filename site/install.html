Install & updates

Redoubt is distributed as signed APKs: through its own F-Droid repository, which also tells you about updates, and on GitHub Releases. Every channel carries the same APKs, signed with the same key.

1. With F-Droid (easiest)

Add Redoubt’s own F-Droid repository — how to add it, with a QR code — and install Redoubt from it. F-Droid then tells you when a new version is out, so nothing else needs setting up. This is not f-droid.org’s main repository: the APKs in it are the release APKs below, with the same signing certificate.

Repository address, for the F-Droid app (a web browser only shows an error there): https://redoubtbrowser.hel1.your-objectstorage.com/repo. Repository fingerprint (the key that signs the index, not the app):

B0A8CDBB61AA4FC3CA1FED71F4CAECEB7B00E39D4E6E0583A637070862AC5567

The repository is hosted in a Hetzner Object Storage bucket, so its address is Hetzner’s and Hetzner sees the IP address and time of each download; the fingerprint, not the address, proves it is Redoubt’s. F-Droid lists Redoubt with the anti-feature “Tracking”, because Redoubt contacts Mozilla services by default: why.

2. With Obtainium

Obtainium is an Android app that watches release pages and offers you new APKs. The project has not tested it with Redoubt yet; this is how it is meant to work:

  1. Install Obtainium from its own release channel (F-Droid or its GitHub page).
  2. In Obtainium, tap Add App and enter the source URL https://github.com/CPlusPlus17/Redoubt. Obtainium recognises it as a GitHub source.
  3. Several APKs are attached to each release. Set Filter APKs by regular expression to arm64-v8a (or armeabi-v7a on older 32-bit devices) so it always takes the right one.
  4. Tap Add. If Redoubt is already installed and Obtainium offers the version you already have, install it once; after that Obtainium tracks releases by their tag.
  5. Obtainium then checks the release page on its own schedule and notifies you; it does not install anything without you confirming.

Obtainium downloads the APK from the same GitHub release, but it does not compare the signing certificate with Redoubt’s published digest for you. Verify the first install yourself, as below. Every update after that is checked by Android: an update signed with any other key fails to install over Redoubt, and Obtainium reports the install error. If that happens, do not uninstall Redoubt to force it in; report it privately.

3. Install the APK directly

  1. Open the latest release on GitHub.
  2. Download the APK for your device — for almost any recent phone that is fenix-arm64-v8a-release.apk — and SHA256SUMS.signed.
  3. Verify it before installing.
  4. Open the APK. When Android asks, allow installs from the app you opened it with, then install.

A newer version installs over the previous one as an update and keeps your data. Android only accepts an update signed with the same key as the installed app, so once you have verified the first install, a tampered update is refused by Android itself. To hear about new versions, turn on the in-app update check or use Obtainium.

Verify the download

sha256sum -c --ignore-missing SHA256SUMS.signed
apksigner verify --print-certs fenix-<abi>-release.apk | grep -i SHA-256

SHA256SUMS.signed lists the hashes of the signed APKs; the file itself is not signed. It catches a corrupted download. The certificate check is what proves the APK is Redoubt’s: the signing certificate’s SHA-256 digest must be

64:14:EB:33:46:81:CF:6E:92:90:34:B5:6A:06:2D:2B:8D:A0:90:82:21:72:F7:A3:95:2C:85:FD:D1:28:3B:D0

which apksigner prints without colons, in lower case:

6414eb334681cf6e929034b56a062d2b8da090822172f7a3952c85fdd1283bd0

Every Redoubt APK is signed with this one key (APK signature schemes v2 and v3). If the digest differs, do not install it, and report it privately. The key and its custody are documented in SIGNING.md.

On the phone

Without apksigner, an app that checks installed apps against published certificates (for example AppVerifier) can do the certificate check right after installation. Give it this, and uninstall Redoubt if it does not match:

org.redoubtbrowser
64:14:EB:33:46:81:CF:6E:92:90:34:B5:6A:06:2D:2B:8D:A0:90:82:21:72:F7:A3:95:2C:85:FD:D1:28:3B:D0

In-app update check (opt-in)

Redoubt has an opt-in update check, off by default (Settings → Check for updates). When you turn it on, it runs only while the app is in the foreground, at most once a day, fetches a small signed file from redoubtbrowser.org/update/, and tells you a new version exists with a link to download it. It does not download or install anything, and it sends nothing that identifies you beyond the request itself. This site is hosted on GitHub Pages, so GitHub sees your IP address and the time of that request. The full contract is in DISTRIBUTION.md.

When F-Droid installed or last updated the app, Redoubt hides the switch: F-Droid already tells you about updates.

Other stores

Redoubt is not on Google Play, Accrescent or f-droid.org’s main repository.

  • Google Play. Redoubt’s release key is never uploaded to Google. If Redoubt is ever published on Google Play, it will use a separate Play-only key, and a Play install and a GitHub or F-Droid install will then not be able to update each other.
  • f-droid.org. f-droid.org can publish developer-signed APKs only if it reproduces the build bit for bit. Redoubt’s build is not reproduced across machines yet, so f-droid.org would sign it with F-Droid’s own key, which makes it a different app to Android.
